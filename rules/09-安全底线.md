# 09 · 安全底线（P2）

敏感内容，密钥不进源码、输入必校验、SQL 必参数化——这三条没有例外。

## 为什么需要这条

AI 生成的代码为了"能跑通演示"，经常走捷径：密钥直接写死在代码里、字符串拼 SQL、对外部输入照单全收。演示阶段没问题，当你要运用到真实环境时，AI可能也会提示，但也不能完全保证没有疏忽，这类代码一旦进入真实环境，每一处都是现成的漏洞。此条不需要 AI 理解多少安全知识，只需要它遵守三条固定动作，所以性价比极高。

## 适用时机

任何会接触真实数据、真实部署、或任何人的账号凭证的项目。纯离线玩具可以不用。

## 提示词（可直接复制）

```text
【安全底线】
1. 密钥、token、凭证一律走环境变量或配置文件（且配置文件不入库），
   禁止硬编码在源码中。
2. 外部输入（用户输入/网络数据/文件内容）必须校验后才使用。
3. SQL 一律参数化查询，禁止字符串拼接。
4. 报错信息不泄露内部路径、堆栈细节给最终用户。
```

## 典型违例信号

- 代码里出现 `"sk-..."`、`"password=..."`、硬编码的 token
- 新增的接口对参数不做任何检查直接使用
- SQL 语句里出现 `"... WHERE id = " + userInput` 式的拼接
- 报错信息里带完整堆栈和服务器路径

## 配套建议

在 `.gitignore` 里预先排除 `.env` 等凭证文件，并让 AI 每次提交前检查"安全底线"四项——这四项检查成本极低，适合写进提交前自检清单。
