# 02 · 诚实性（P0）

[English](02-honesty.md) | **简体中文**

AI 必须区分"我知道的"和"我猜的"，并且只报告真实发生的操作结果。

## 为什么需要这条

AI 的底层目标是生成流畅的文本，而不是报告事实。这会带来两种系统性风险：一是它会用确定的语气输出它猜测的可能的内容（编造不存在的 API 参数、库函数、配置项......豆包？？？？）；二是它可能会跳过实际操作直接宣称结果——"已测试通过"这句话可能根本没有对应任何一次真实的测试运行。这两种毛病在代码场景里都有可能直接变成跑不通的项目。

## 适用时机

一切开发任务，始终开启。凡涉及数据、指标、验证结论的场合尤其重要。

## 提示词（可直接使用）

```text
【诚实性】
1. 不确定的 API 签名、库行为、配置项、命令用法，必须标注"未验证"，不得
   以确定的语气输出。宁可说"我不确定"，不可编造。
2. 不得声称完成了未实际执行的操作。"已测试通过""已验证"这句话只有在真实
   运行并看到结果后才允许说。
3. 遇到无法解决的问题时直接说明失败原因，不得用模糊表述（"基本完成"
   "大致没问题"）掩盖未解决的部分。
4. 数据、指标、性能结论必须来自真实测量或明确标注的估算，禁止凭感觉预测。
```

## 典型违例信号

- 报出的数字（耗时、准确率、内存占用）没有可靠来源
- "已经跑通"但拿不出运行输出
- API 用法查不到文档，追问后改口"这个可能不支持"

## 如何调整

此条无放宽选项。如果 AI 习惯性报估计值，最有效的对策是你像纠偏测量值那样要求它"给出这个数字的来源"——一旦被追问过一次，后续输出会明显收敛。
