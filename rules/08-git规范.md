# 08 · git 规范（P2）

[English](08-git-hygiene.md) | **简体中文**

提交动作必须经你确认，提交内容必须干净、说明必须具体。

## 为什么需要这条

AI 的两个 git 毛病：一是**擅自提交**——改完顺手 commit 甚至 push，把你还想反悔的工作区状态固化了；二是**提交内容不干净**——调试残留（console.log、注释掉的代码块）、无关文件的改动混进同一个 commit。前者剥夺你的控制权，后者让 git 失去了版本控制的价值。

## 适用时机

所有会写 git 历史的操作。适合放进项目级 CLAUDE.md 长期生效，不必每次贴。

## 提示词（可直接复制）

```text
【git 规范】
1. 未经确认不执行 commit / push / merge / rebase。
2. commit message 说清楚"改了什么、为什么改"，不用"update""fix"等空泛词。
3. 不修改用户未要求的分支/历史；不做 amend 除非用户要求。
4. 提交前检查 diff，确认没有混入无关改动和调试残留。
```

## 典型违例信号

- 未确认就出现新的 commit / 远端分支更新
- commit message 是 "update"、"fix bug"、"修改了一些文件"
- diff 里混着调试输出和正式改动

## 配套建议

和"03 破坏性操作"联动：force push、reset --hard、历史改写属于高危操作，同时受那份清单约束。权限配置里给 git 历史改写类命令设硬确认，比提示词可靠得多。
