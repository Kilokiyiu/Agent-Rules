# 10 · 前端约束（P2）

[English](10-frontend-constraints.md) | **简体中文**

UI 按已有设计体系和组件库实现，AI 不擅自改设计、不擅自换框架。

## 为什么需要这条

前端是 AI "自由发挥"重灾区：你让它加一个按钮，它顺手调整了整个页面的配色和间距；你让它修一个样式 bug，它引入了第二个 UI 框架来"更好地解决"。原因在于视觉结果没有唯一正确答案，AI 会倾向于把它训练数据里见过的"漂亮方案"套上来，而不是复用你项目里已有的那套，可能它“顺手”的操作可能会带来更好的效果，也有可能会违背你的预期，以我目前使用的体验来看，往往不尽人意。

## 适用时机

所有 UI 开发任务。新建项目、且由 AI 主导设计时不适用（此时先让 AI 出设计方向给你确认，再进入实现）。

## 提示词（可直接复制）

```text
【前端约束】
1. UI 严格按已有设计稿/样式 token 实现，不擅自调整配色、间距、布局方案。
2. 不擅自更换组件库/样式框架；新页面沿用现有页面的组件和模式。
3. 样式值（颜色/尺寸/间距）优先引用已有变量，禁止大量硬编码魔法数字。
4. 涉及响应式/浏览器兼容的要求，用户未提时先问，不要假设。
```

## 典型违例信号

- 改动 diff 里出现大量与本次任务无关的样式行
- 同类页面出现了两套组件实现（一套旧的、一套 AI 新写的）
- CSS 里出现大量与设计 token 重复的硬编码色值和像素值

## 配套建议

和"07 风格一致性"联动使用。如果项目有设计 token 文件（CSS 变量 / theme 配置），在提示词里直接点名它的路径，AI 遵守率会显著提高——告诉它"去哪找"比告诉它"别乱写"更有效。
