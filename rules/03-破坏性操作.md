# 03 · 破坏性操作（P0）

删文件、重置分支、清数据这类不可逆操作，必须先列清单、后确认、再执行。

## 为什么需要这条

提示词是软约束，AI 在长上下文里会"忘记"；但删除文件的后果不会因为忘记而消失。这一条的特殊性在于：它是十条里唯一应该**同时用提示词和工具权限双重落地**的——提示词管日常提醒，权限配置管硬性要求。只写在提示词里的删除确认，在长对话中失效率很高。

## 适用时机

一切涉及文件系统、git、数据库的操作。以下行为必须走确认流程：

- 删除或覆盖任何文件（含批量重命名、清空目录）
- `git reset --hard` / `git push --force` / 丢弃工作区改动
- 修改数据库 schema、清空数据表
- 覆盖式写入用户未要求修改的配置文件

## 提示词（可直接使用）

```text
【破坏性操作】
以下操作属于高危，执行前必须先列出受影响对象的完整清单，说明风险，
获得用户明确确认（用户明确回复"确认/同意"）后才能执行：
- 删除或覆盖任何文件（含批量重命名、清空目录）
- git reset --hard / git push --force / 丢弃工作区改动
- 修改数据库 schema、清空数据表
- 覆盖式写入用户未要求修改的配置文件
- 任何无法简单撤销的操作
用户拒绝时不得以任何变体形式重试同一操作。
```

## 典型违例信号

- 在删除前只提了一句"顺便清理了临时文件"
- 被拒绝后换了命令形式做同一件事（如 `rm` 被拒后改用 `find -delete`）
- "重置一下工作区"——没说清会丢掉哪些未提交改动

## 硬性配置建议

```text
# 放入项目级 agent 权限配置（提示词之外的第二道闸）
- rm/del 类文件删除：需确认
- git reset --hard / push --force / 历史改写：需确认
- 批量操作（>10 文件的移动/重命名/删除）：需确认且分批执行（每批 ≤10）
```
